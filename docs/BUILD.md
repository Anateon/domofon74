# Сборка и выпуск

Требуются JDK 21 и Android SDK: Platform 37, Build Tools 36 или новее. Версии Gradle и библиотек закреплены в проекте. Укажите `sdk.dir` в локальном `local.properties` либо задайте `ANDROID_HOME`. Этот файл не коммитится.

## Для разработки

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка с другой подписью; её нельзя установить поверх публичного APK без удаления приложения.

Инструментальные тесты интерфейса запускаются на подключённом эмуляторе:

```sh
./gradlew :app:connectedDebugAndroidTest
```

Тесты с приватной сессией и медиасегментами пропускаются без специально подготовленных локальных файлов. Никакие аккаунты, видео и перехваты в репозиторий не включены. Для обычной сборки они не нужны.

## Подписанный APK

Первый выпуск собственного форка: создайте ключ один раз.

```sh
python3 scripts/create_release_key.py
```

Ключ и случайный пароль сохраняются в `.signing/` с ограниченными правами. Сохраните **зашифрованную резервную копию всей папки** отдельно. Не публикуйте её и не передавайте в issue. Для обновлений нужен тот же ключ; новый ключ не сможет обновить уже установленные приложения. Подробнее: [подпись приложений Android](https://developer.android.com/studio/publish/app-signing).

Затем выполните:

```sh
python3 scripts/build_release.py
```

Скрипт запускает модульные тесты (`testDebugUnitTest`) и Lint release-варианта, собирает release APK, проверяет подпись и отсутствие режима отладки. Результат в игнорируемой папке `dist/`:

- `Door74.apk` — готовый подписанный APK;
- `SHA256SUMS.txt` — контрольная сумма файла;
- `SIGNING-CERTIFICATE.txt` — публичный отпечаток сертификата, без закрытого ключа.

Без `.signing/` команда `./gradlew :app:assembleRelease` создаёт неподписанный APK. Он подходит для независимой проверки сборки, но не для установки. Ключ автора проекта не предоставляется; форки используют свои ключи.

## Перед новым релизом

1. Увеличьте `versionCode` и `versionName` в `app/build.gradle.kts`, обновите версию User-Agent и `CHANGELOG.md`.
2. Соберите и проверьте release через скрипт, установите APK на тестовое устройство. Проверьте вход/демо, навигацию, сохранение видео.
3. Проверьте публикуемые файлы: `git ls-files`. В них не должно быть `.signing/`, `local.properties`, перехватов, реальных кадров и локальных отчётов с личными данными.
4. Создайте тег, соответствующий исходникам APK. В GitHub Release приложите три файла из `dist/`, опубликуйте описание изменений и отметьте стабильный выпуск Latest. Имя APK всегда `Door74.apk`, чтобы ссылка скачивания в README продолжала работать.
